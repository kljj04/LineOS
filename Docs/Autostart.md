# 사용자 시작 프로그램

로그인 성공 후 사용자 UID/GID로 전환하고 홈 디렉터리로 이동한 세션 프로세스가 `~/.config/autostart`를 읽습니다. 시작 프로그램을 각각 fork/execve로 실행하고, 끝나기를 기다리지 않은 채 로그인 쉘도 별도 자식으로 실행합니다. 시작 프로그램 실패 시에도 쉘을 실행합니다.

설정이 없으면 `.config` 디렉터리와 다음 내용의 파일을 사용자 권한으로 생성합니다. 기존 파일은 덮어쓰지 않습니다.

```text
/sys/lwm/lwm.lix
```

파일은 한 줄에 실행 파일의 절대 경로 하나를 지정합니다. 빈 줄과 #으로 시작하는 줄은 건너뜁니다. 줄 앞뒤 공백과 CRLF를 처리합니다. 인자, 쉘 문법, 변수 및 PATH 검색은 지원하지 않습니다. 한 줄은 최대 4095바이트, 시작 프로그램은 최대 32개입니다.

현재 사용자 설정을 비워 자동 실행을 끌 수 있습니다.

```sh
echo -n "" > "$HOME/.config/autostart"
```

다시 lwm을 등록할 수 있습니다.

```sh
echo /sys/lwm/lwm.lix > "$HOME/.config/autostart"
```

일반 시작 프로그램의 표준 입력은 `/dev/null`입니다. 표준 출력과 오류는 기존 터미널에 연결됩니다. GUI 프로그램은 기존 인터페이스로 TTY와 화면 소유권을 직접 요청합니다.

lwm 실행 시 공용 Terminal도 IPC 클라이언트로 연결되어 쉘을 바닥 레이어로 표시하고 GUI 창들을 그 위에 표시합니다. 하드웨어 입력은 lwm이 읽고, 포커스가 있는 창에 키를 전달합니다. Terminal은 받은 키를 별도의 전달 입력 큐로 쉘에 보냅니다. lwm을 닫아야 CLI를 사용하는 방식은 아닙니다. 자세한 창 조작 및 현재 크기 변경 제약은 Lwm.md를 참조합니다.

세션은 쉘과 직접 실행한 모든 시작 앱을 수거한 후 로그인 화면으로 돌아갑니다. 따라서 쉘이 종료되어도 시작 앱이 계속 살아 있으면 세션은 그 앱의 종료를 기다립니다. 로그아웃 시 앱을 강제 종료하는 정책은 아직 시그널 전달 구현이 필요합니다. 앱이 fork한 자손 전체를 세션 단위로 관리하는 기능도 포함하지 않습니다.

빌드 및 실행 검증은 수행하지 않았습니다.
