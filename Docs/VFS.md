# VFS 코어와 커널 개발 셸

## 경로와 표시

확정된 구분은 다음과 같다.

- 각 파티션에는 독립적인 PROOT `/`가 있다. `/A/B/C`는 현재 선택한 파티션의 경로다.
- AROOT `^`는 파티션을 고르는 가상 관리자 루트다. 파일시스템의 실제 디렉터리가 아니다.
- 관리자라도 파티션 안에 있으면 표시 경로는 `/A/B/C`다. 권한 상승 자체가 접두사나 cwd를 바꾸지 않는다.
- 실제 AROOT에 있는 컨텍스트만 `^`를 표시한다.
- 일반 컨텍스트는 UID가 0이어도 Administrator 권한이 없으면 AROOT 조회·탐색·목록화에 `VFS_NOT_FOUND`를 받는다.

이번 코어의 보수적인 선택 문법은 `^/Root/A/B`다. AROOT에서 상대 경로 `Root/A/B`로도 같은 파티션을 선택한다. 별칭은 등록 시 정하는 대소문자 구분 이름이며 영문·숫자·밑줄·하이픈 1~31자다. 이 별칭 세부 문법을 예전 대화에서 확정됐다고 간주하지 않는다.

`/`는 AROOT에 있는 경우에도 마지막 선택 파티션의 PROOT를 뜻한다. PROOT의 `..`는 PROOT에 머무르며 AROOT로 빠져나가지 않는다. 일반 상대 경로는 현재 파티션과 물리적으로 해석된 cwd를 기준으로 한다. 심볼릭 링크를 먼저 따라간 뒤 `..`를 처리하므로 `/Link/..`를 문자열만으로 미리 축약하지 않는다.

절대 심볼릭 링크 `/A`는 링크가 속한 파티션의 PROOT를 기준으로 한다. 심볼릭 링크로 AROOT에 진입하거나 파티션을 바꾸는 동작은 관리자에게도 허용하지 않는다. `^`로 시작하는 경로 요소는 예약한다. 경로는 최대 4095바이트, 파일 이름은 255바이트, 링크 확장은 40회로 제한한다. 생성·삭제·이름 변경의 마지막 이름에는 후행 `/`, `.`, `..`를 허용하지 않는다. URL 인코딩, 글로브, 환경 변수 확장은 없다.

## 명령 컨텍스트와 sudo cd

`VFSBeginCommand()`는 세션의 위치와 자격 증명을 명령 컨텍스트에 복사한다. 권한 상승의 `Authorized`는 신뢰하는 커널/셸 인증 계층에서 제공하는 결과이며 인증을 수행하는 함수가 아니다. `VFSEndCommand()`는 명령 자격 증명을 폐기한다. 일반 외부 명령은 위치를 반환하지 않고, 성공한 `cd` 같은 셸 내장 명령만 위치를 세션에 돌려준다.

- `sudo cd ^/Root/A`: 이후 세션의 파티션과 cwd는 Root와 `/A`가 된다. 사용자 UID/GID와 관리자 여부는 원래대로 유지된다.
- `sudo ls ^`: 그 명령에서만 파티션을 나열한다.
- `sudo cd ^`: AROOT 위치와 `^` 프롬프트를 유지한다. 관리자 권한은 내려가므로 그 위치에서 일반 `ls`는 실패하고 `sudo ls`로 조회한다. `pwd`는 현재 위치만 표시한다.

## 구현과 수명 계약

`Kernel/Include/FS/VFS`와 `Kernel/Source/FS/VFS`에 파티션 레지스트리, 경로 해석, 컨텍스트, 디렉터리 열거, 파일 연산, EXT2 백엔드가 있다. EXT2 백엔드는 기존 API를 사용하고 각 연산 후 원래 자격 증명을 복원한다. 등록 파티션 수는 최대 32개다.

레지스트리 안의 연산은 비차단 배타 진입으로 직렬화한다. 사용 중인 레지스트리에는 `VFS_BUSY`를 반환한다. 컨텍스트는 한 소유자가 사용해야 하며, 마운트·등록·해제·레지스트리 수명은 초기화 소유자가 직렬화한다. 등록한 EXT2 볼륨을 다른 레지스트리나 직접 EXT2 호출로 동시에 사용하면 안 된다. 같은 파티션의 중복 쓰기 마운트도 호출자가 방지해야 한다.

`VFSMountEXT2()`는 GPT 인덱스를 받고 Linux filesystem GUID를 검증한다. 현재 커널은 p2를 Root로 마운트한다. EFI p1은 관리자 목록에 예약된 EFI 이름으로 등록하지만 백엔드는 없다. 접근하면 `VFS_UNSUPPORTED`이며 FAT32 지원이 완성된 것으로 취급하지 않는다.

프로세스별 파일 디스크립터, 열린 파일 참조 수, 삭제된 열린 파일의 수명, 사용자 모드 시스템 호출은 아직 없다. 경로 기반 파일 연산과 개발 셸은 실제 구현됐지만 완전한 POSIX VFS 또는 유저랜드는 아니다.

## UTC와 EXT2 시간

기존 명시적 `UINT32 Time` 인자는 호환성을 위해 유지한다. 커널 테스트 호출부는 더 이상 Time=0을 넘기지 않고 `ClockGetUnixTime()`의 UTC Unix 초를 넘긴다. VFS의 변경 연산은 `EXT2GetCurrentTime()`으로 시간을 얻으며 준비되지 않은 시계 또는 표현 범위 초과이면 변경 전에 실패한다.

- atime: 접근 시각. 파일 읽기·디렉터리 열거·링크 읽기에 relatime 정책을 적용한다. ctime/mtime보다 이전이거나 하루 이상 지난 접근 시각을 갱신한다. 읽기 전용 마운트에는 쓰지 않으며 inode의 noatime 플래그도 존중한다.
- ctime: inode 메타데이터 변경 시각. 생성 초기화, 쓰기, 축소/확장, 소유자·권한·링크 수·이름 변경 등에 갱신한다.
- mtime: 데이터 변경 시각. 파일 쓰기·크기 변경과 디렉터리 항목 변경 시 갱신한다.
- crtime: 일반 EXT2에 별도 필드가 없으므로 만들거나 ctime을 생성 시각으로 해석하지 않는다.

`touch`는 atime·mtime을 현재 UTC로 설정하고 이 변경의 ctime도 갱신한다. 한국 시간 표시를 위한 ClockGetDateTime의 UTC offset은 디스크 시간에 적용하지 않는다. 런처의 RTC는 UTC 기준이다. Clock 초기화 실패 시 커널이 실패를 알리며 1970년 시간으로 조용히 테스트를 진행하지 않는다.

## 변경 블록 한도

기존 1024개에서 32768개로 늘렸다. 1/2/4KiB 블록에서 데이터와 메타데이터를 합쳐 약 32/64/128MiB까지 한 변경에 준비할 수 있다. 데이터 전체 크기 한도가 아니며 메타데이터 때문에 한 번에 쓸 수 있는 순수 데이터는 조금 작다.

수정 블록은 해시 버킷으로 찾고 실제 블록 크기만큼 메모리를 할당한다. 메모리 부족과 한도 초과는 커밋 전에 중단한다. 저널·장치 고장·실제 전원 차단에 대한 원자성 보장은 추가하지 않았다.

## 개발 셸

`Kernel.c`의 `KernelShellTask()`가 기존 EXT2/VFS 테스트 성공 후 p2를 다시 쓰기 마운트해 실행된다. 입력 모니터와 시계 태스크는 유지한다. 셸·입력 화면·시계·디스크 테스트의 렌더링 호출은 비차단 게이트로 직렬화한다. 이 게이트는 스케줄러나 일반 커널의 부동소수점 컨텍스트 지원을 추가하는 것이 아니다.

초기 사용자 프로필은 UID/GID 1000이며 새로 만드는 `/Home/User`를 소유한다. 기존 홈이 있으면 소유권을 강제로 덮어쓰지 않는다. QHD에서는 오른쪽 패널을 사용하며 낮은 해상도에서는 입력 화면 아래 영역을 사용한다. 최소 640x900이 필요하다.

이 셸은 로컬 개발 콘솔이며 로그인이나 암호 인증을 하지 않는다. `sudo`는 콘솔 조작자에게 명령 한 번의 권한 상승을 허용하는 개발 정책이다. 일반 OS의 보안 인증 계층이 구현된 것은 아니다.

| 명령 | 사용법 |
|---|---|
| help, pwd, cd, ls | 도움말, 현재 경로, 이동, 디렉터리 목록 |
| stat, cat, hexdump | 파일 정보, 텍스트 출력, 앞 256바이트 16진수 출력 |
| mkdir, touch | 디렉터리 생성, 빈 파일 생성/시간 갱신 |
| write PATH TEXT | 파일 생성 또는 잘라낸 뒤 TEXT 저장 |
| append PATH TEXT | 파일 끝에 TEXT 추가 |
| cp SRC DST, mv SRC DST | 파일 복사, 같은 파티션 이름/위치 변경 |
| rm PATH, rmdir PATH | 파일·심볼릭 링크 삭제, 빈 디렉터리 삭제 |
| ln SRC DST, ln -s TARGET PATH | 하드 링크, 심볼릭 링크 생성 |
| truncate SIZE PATH | 바이트 단위 파일 크기 변경 |
| chmod OCTAL PATH | 8진수 권한 변경 |
| chown UID GID PATH | 소유자·그룹 변경; 권한 필요 |
| echo, time, uptime, whoami | 문자열, UTC Unix 초, 부팅 후 초, 현재 명령 자격 증명 |
| sync, clear, history | 디스크 flush, 화면 지우기, 최근 명령 |
| sudo COMMAND | 개발 콘솔의 명령 한 번 권한 상승 |

입력은 US 키 배열의 ASCII, Shift/Caps Lock, Backspace, 위·아래 최근 명령 회수를 지원한다. 따옴표와 백슬래시로 공백을 포함한 인자를 입력할 수 있다. 명령 줄은 511바이트, 토큰은 12개, 최근 명령은 16개다. Ctrl+C/Ctrl+U는 편집 중인 줄을 지우고 Ctrl+L은 출력도 지운다. 실행 중인 I/O를 중단하는 프로세스 시그널은 없다.

`cat`의 화면 출력은 64KiB로 제한한다. 복사와 실제 파일 읽기/쓰기는 이 화면 제한과 무관하다. write·cp는 저널 없는 일반 파일 연산이며 중간 I/O 오류 시 대상 파일이 부분적으로 바뀔 수 있다. 파이프·리디렉션·프로세스 실행·재귀 삭제는 없다.

## 검증

`python3 Tests/FS/Run.py --work /tmp/LineOSFSTests`는 ASan/UBSan과 경고 오류 처리로 실제 Clock·EXT2·VFS·Kernel.c 셸 명령 코드를 실행한다. 테스트 장치·시계 입력만 호스트 어댑터로 바꾼다. 실제 Clock 변환 검사는 RTC와 TSC 입력을 제어한다.

2026-10-19 검사에서 시계 13개, 블록 크기 1/2/4KiB 각각 파일시스템/VFS 144개, 셸 명령 코드 117개 검사가 통과했다. 두 파티션 분리, AROOT 은닉과 링크 우회 거부, 명령 컨텍스트 해제, cwd 유지, 타임스탬프 의미, 5MiB 단일 쓰기, 할당 실패 후 준비 상태 폐기를 검사했다. 모든 결과 이미지가 e2fsck를 통과했다.

QEMU/KVM 1CPU·16CPU에서 실제 VirtIO 키보드 입력으로 각각 27개 명령을 시험했다. 정상 결과뿐 아니라 권한 거부, AROOT 은닉, 자기 파일 복사 거부, sudo 권한 회수도 포함했다. 기존 EXT2/VFS 테스트 PASS와 결과 디스크의 e2fsck 통과도 확인했다. 이 결과는 전체 스케줄러 공정성, 모든 장치, 실제 전원 차단을 검증한 것은 아니다.

`sudo cd ^` 위치 유지 변경 후 호스트 검사를 다시 통과했다. 1CPU 부팅에서도 `sudo cd ^`, `pwd`, 일반 `ls` 거부와 `sudo ls` 성공을 확인했다.
