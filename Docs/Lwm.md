# lwm

실행 파일은 기존 설정에 따라 `/sys/lwm/lwm.lix`에 설치됩니다. 로그인 시 사용자 시작 프로그램에서 실행합니다. 최초 화면은 장식 없는 배경 쉘입니다. 쉘을 일반 창 목록에 넣지 않으며 내부 데모 창을 자동으로 만들지 않습니다. 터미널의 첫 창 프레임을 받기 전에는 데스크톱 프레임으로 화면을 덮지 않습니다. 5초 내 터미널이 연결되지 않으면 종료하고 CLI 경로로 복귀합니다.

## 창과 입력

lwm은 창 테두리, 제목 표시줄, 그림자, 최소화·최대화·닫기 버튼과 하단 독을 그립니다. 일반 GUI 창에는 12px 모서리 라운딩과 경계의 4×4 커버리지 AA를 적용하며 최대화 상태는 각진 모서리를 사용합니다. 앱은 내용 영역의 픽셀만 제공합니다.

- 제목 표시줄로 창을 이동합니다.
- 모든 변과 모서리를 안쪽 6px 영역에서 끌어 크기를 조절합니다. 최대화된 창은 복원한 뒤 조절합니다.
- 최소화한 창은 독에서 복원합니다.
- 최대화 버튼은 패널과 독을 제외한 영역으로 확장하며 다시 누르면 이전 위치와 크기를 복원합니다.
- 일반 창의 닫기는 앱에 닫기 이벤트를 보내고 표시에서 제거합니다. 강제 프로세스 종료는 아닙니다.
- 공용 Terminal 프레임은 배경 레이어입니다. 제목 표시줄·테두리·최소화·최대화·닫기 버튼을 적용하지 않습니다.
- 독의 TestGUI + 버튼은 별도 TestGUI 프로세스를 실행합니다. 클릭한 창이 앞으로 이동하고 키 입력을 받습니다.
- 독의 종료 버튼은 lwm을 종료합니다. 앱에 q나 Escape를 입력하는 것으로 lwm을 종료하지 않습니다.

Terminal과 TestGUI는 별도 프로세스로 동작합니다. Terminal 프레임을 먼저 바닥에 합성하고 GUI 창과 그림자, 독을 그 위에 합성합니다. 가려지지 않은 쉘 영역을 클릭하거나 독의 Shell 버튼을 누르면 CLI가 키 입력을 받습니다. GUI 창을 클릭하면 해당 창이 키 입력을 받습니다. 창을 닫거나 최소화해도 배경 쉘은 계속 유지됩니다. TestGUI는 서버가 없으면 기존 전체 화면 실행 경로를 사용합니다. Terminal은 기존 마스터 출력 큐를 계속 처리하면서 IPC 창에 프레임을 보냅니다. 커널은 GUI가 읽는 하드웨어 입력과 Terminal이 쉘에 전달하는 입력 큐를 구분합니다. 따라서 lwm과 쉘이 같은 키를 먼저 가져가려는 경쟁을 피합니다.

크기 변경은 GUI 클라이언트의 고정 해상도 버퍼를 최근접 보간하여 표시합니다. 배경 쉘은 독을 제외한 화면 영역에 원래 픽셀 크기로 표시합니다. 확대·축소에 따른 네이티브 레이아웃 변경과 터미널 열·행 재배치는 아직 없습니다. 좌표 이벤트는 원래 클라이언트 해상도로 환산합니다. 현재는 공용 배경 콘솔 하나이며 여러 독립 터미널 세션을 만드는 기능은 포함하지 않습니다.

## 합성과 갱신

창마다 클라이언트 프레임과 수신 중인 프레임, 장식용 버퍼를 분리합니다. 클라이언트는 변경된 행을 PIXELS 메시지로 전송하고 PRESENT로 묶음을 확정합니다. lwm은 확정 전의 부분 프레임을 표시하지 않습니다. 창 제목·독 글리프는 캐시합니다. 쉘 변경 행, 창의 이전·현재 위치와 그림자, 독 상태를 기준으로 바뀐 영역만 다시 합성합니다. 그림자는 내부 면적을 순회하지 않고 윤곽만 계산합니다. 합성 결과는 필요한 사각형으로 묶어 framebuffer present ioctl로 전달합니다. 변경 없는 배경 전체 복사와 비교는 반복하지 않습니다.

화면 갱신 상한은 단조 시계 기준 120Hz, 주기는 약 8.333ms입니다. 변경이 없으면 화면을 다시 그리지 않습니다. 실제 도달 주파수는 CPU 합성 비용, IPC 전송, 타이머 정밀도 및 GPU present 비용에 따라 달라지며 120FPS를 검증한 것은 아닙니다.

창은 최대 8개입니다. IPC 클라이언트 내용 크기는 최대 2560×1440, framebuffer는 640×480부터 4096×2160의 연속된 32비트 RGB 행을 요구합니다. 공용 Terminal의 기존 framebuffer 최대 크기는 2560×1440입니다.

빌드·이미지 배포·QEMU 실행은 수행하지 않았습니다.

기존 쉘 프로세스와 입력 상태, 출력 줄 및 기록을 유지합니다. GUI 연결·해제 시 화면 모델 전체를 초기화하지 않고 독에 필요한 높이만 조정합니다. 쉘과 히스토리는 새로 생성하지 않습니다.

입력 처리는 합성 주기와 분리하여 최대 1ms 간격으로 확인합니다. 화면 합성 상한은 계속 120Hz입니다. Terminal은 바뀐 텍스트 행, 이전·현재 커서, 스크롤바 변경을 추적하여 해당 행만 비교하고 전송합니다. 글자 입력마다 전체 프레임을 비교하던 경로는 사용하지 않습니다. 이 변경의 실제 응답 지연 및 CPU 사용량은 측정하지 않았습니다.
